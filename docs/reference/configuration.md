# Configuration

Every `CurioConfig` field, its default, and what it does.

`CurioConfig` is the framework's configuration surface. Set it once, early, from your OpMode's
initialization hook, before the control loop starts.

```java
@Override
public void initRobot() {
    CurioConfig.DEBUG = false;
    CurioConfig.LOGGING_ENABLED = false;
    CurioConfig.TELEMETRY_PERIOD_MILLIS = 200;
    robot = new CurioRobot(hardwareMap);
}
```

## Fields

### `DEBUG`

```java
public static boolean DEBUG = false;
```

**Default:** `false`

When enabled, the framework emits `DEBUG`-category telemetry and verbose diagnostic messages.

Off by default so a competition run stays quiet. Enabling it adds no measurable cost to the
control loop, but it does add console traffic. Turn it on when debugging, turn it off before a
match.

### `TELEMETRY_PERIOD_MILLIS`

```java
public static int TELEMETRY_PERIOD_MILLIS = 200;
```

**Default:** `200` (five flushes per second)

The minimum interval between telemetry flushes. Set `0` to flush every loop.

The default is a compromise: fast enough to feel live while watching, slow enough that telemetry
does not eat the loop budget. Values below `0` are treated as `0`.

### `LOGGING_ENABLED`

```java
public static boolean LOGGING_ENABLED = false;
```

**Default:** `false`

Enables structured CSV logging to Robot Controller storage.

Disabled by default, and that is not negotiable by default: logging writes to storage and must be
an explicit choice so it can never interfere with a match. See
[telemetry and logging](../guides/telemetry-and-logging.md).

### `version()`

```java
public static String version();
```

Returns the framework version — for example `"0.1.0"` — or `"unknown"` if the build metadata is
missing. The value is generated by the build from the same property the artifact is published with,
so it cannot drift from the jar.

Log it at the start of a match to record exactly which build a run used.

## Thread safety

`CurioConfig` is **not** thread-safe. Configure it from the OpMode thread before the control loop
starts, then treat it as read-only. Reading a field is safe from that same thread.

## What is not here

Physical constants — wheel diameter, gear ratio, ticks per revolution, arm positions, motor names.
Those belong to your robot, in your `RobotConfig` class. The framework never contains them; see
[robot configuration](../guides/robot-config.md).
